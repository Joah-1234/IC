TACL 代码实现与复现思路总结
本次复现的核心目标是实现一种**针对未知攻击具有强泛化能力**的人脸活体检测框架。为了达成这一目标，代码编写遵循了以下六大核心思路：

1. 数据层：物理隔离与严谨清洗 (Data Hygiene)
数据质量决定了对比学习的上限。我们放弃了简单的文件名匹配，转而采用更严谨的结构化清洗策略。

跨域协议隔离：严格遵循 Leave-One-Out (OCI-to-M) 协议。将 OULU-NPU, CASIA-MFSD, Replay-Attack 作为训练源域，MSU-MFSD 作为不可见的测试目标域，在物理文件夹上进行彻底隔离，杜绝数据泄露。

基于结构的分类 (Structure-based Sorting)：借鉴 SSDG 的处理逻辑，编写 safe_sort_v5.py。不依赖模糊的文件名关键词，而是通过解析数据集原始的文件夹层级（如 /real/ 目录、Video ID 列表、Type Code）来精确划分 Live/Spoof。

模态提纯：TACL 是基于 RGB 的视觉模型。我们在预处理阶段增加了严格的过滤器（文件名过滤 + 像素级检测），剔除了数据集混入的 Depth（深度图）、IR（红外图）和全黑损坏图，防止模型学习到“黑白=真脸”的错误捷径。

2. 输入层：双视图构造与鲁棒加载 (Input Pipeline)
为了支撑对比学习（Contrastive Learning），数据加载器必须能够构造“正样本对”。

双视图变换 (Two-Crop Transform)：在 ocim_dataset.py 中实现特殊的 Transform，对同一张输入图像进行两次独立的随机增强（随机裁剪、颜色抖动、翻转），生成 View1 和 View2。这是 TAC Loss 拉近同一真脸在不同增强下特征的基础。

异常熔断机制：修复了 DataLoader 在读取失败时返回“全黑 Dummy Image”的逻辑漏洞，改为直接抛出异常。确保模型“要么吃好数据，要么报错”，避免了学习无效特征导致的 Loss 卡死。

3. 模型层：Token 级特征提取 (Model Architecture)
算法核心在于关注局部攻击痕迹，而非全局语义。

Backbone 选择：使用 timm 加载 ImageNet 预训练的 ViT-Base-Patch16-224。利用 Transformer 的 Token 机制天然对应图像 Patch。


特征聚合策略：放弃了常见的 CLS Token 或 Average Pooling，采用 Global Max Pooling (GMP) 。


设计思路：欺骗痕迹（如纸张边缘、屏幕摩尔纹）通常是局部的。Max Pooling 能最大化保留这些显著的攻击特征，而 Average Pooling 可能会平滑掉这些微小痕迹。

双头设计：

投影头：用于计算 TAC Loss 的特征空间投影。

分类头：ArcFace Layer，用于计算 AM Loss 的分类边界。

4. 损失层：非对称对比设计 (Asymmetric Loss Design)
这是 TACL 区别于传统方法的灵魂所在，旨在解决“未知攻击”问题。


TAC Loss (聚类)：实现了**“不对称”**的逻辑 。


Live-Live (Pull)：强力拉近。无论来自哪个域，真脸必须在特征空间塌缩成一个点。

Live-Spoof (Push)：强力推开。真假之间必须有 Margin。

Spoof-Spoof (Ignore)：不做任何约束。允许假脸特征发散。这是为了应对未知攻击——因为未知的假脸不需要长得像已知的假脸，只要不像真脸即可。

AM Loss (分类)：引入 Angular Margin Loss，在超球面上切分出真脸的专属扇区，辅助模型快速收敛。

5. 训练层：稳定性与防崩盘策略 (Training Stability)
在大规模跨域数据（38万+张图）上训练 ViT 极易出现数值不稳定，我们采取了“防御性编程”：

全精度训练 (FP32)：放弃 AMP 混合精度，避免 exp() 运算在 FP16 下溢出导致 Loss NaN。

梯度裁剪 (Gradient Clipping)：设置 max_norm=1.0，强行截断过大的梯度，防止参数更新导致权重飞出有效范围。

学习率策略：采用较小的初始学习率 (5e-5) 配合 Warmup，防止冷启动时模型震荡。

权重验证：在加载预训练权重时增加 Key 匹配检查，防止模型在“裸奔”（随机初始化）状态下训练。
